# AnimaFlux 是什么？

> 让 AI 的情绪和关系不会在每次对话结束后突然归零。

[English README](README.md)

## 先说人话

普通聊天模型很容易出现一种割裂感：上一刻刚和你吵完架，下一次回复却像什么都没发生；明明已经聊到凌晨，它仍然精神饱满；嘴上说很在意你，长期相处却没有留下任何可以检查的变化。

AnimaFlux 是放在聊天模型外面的一本“状态账”。它记录角色此刻的情绪、关系感受、未解决的事情、困意和表达倾向，再把与当前对话有关的部分交给模型参考。

它不会替换角色原本的人设，也不是一份新的系统人设。它只负责告诉模型：**经历了前面的事情以后，这个角色现在处在什么状态，以及这种状态应该怎样影响说话。**

## 举个例子

假设用户和角色晚上吵了一架，然后两个小时没有说话。

没有状态连续性时，模型可能只根据眼前一句“在吗”重新开始，回复得像第一次见面。

接入 AnimaFlux 后，系统可以保留这些信息：

- 刚才的冲突还没有解决；
- 角色有点生气，也有想靠近和解释的冲动；
- 用户长时间没有回复，让想念和不安发生了变化；
- 现在已经很晚，困意会让句子变短、反应变慢；
- 这些状态应该影响语气，但不能捏造新的事实。

模型最终仍然自己组织语言。AnimaFlux 提供的是当前状态和表达方向，不是一段必须照抄的台词。

## 它记录什么？

目前的状态结构包括：

- **短期情绪**：开心、难过、生气、焦虑、疲惫等；
- **长期关系**：信任、安全感、依恋深度、熟悉程度等；
- **内在倾向**：脆弱感、分享欲、困意和精力；
- **关系余波**：例如一次争吵留下的未解决张力；
- **昼夜节律**：清醒、犯困、睡着、半梦半醒和逐渐醒来；
- **表达提示**：把状态变成对句子长度、语气、主动程度等方面的指导。

不同状态不会一起随时间机械下降。短期情绪可以自然缓和，而信任和依恋等长期关系通常由真实事件改变。

## 它怎么工作？

每次收到一段新对话时，AnimaFlux 大致会做五件事：

1. 读取上一次留下的状态；
2. 根据经过的时间让部分短期状态自然变化；
3. 结合当前消息和取回的相关记忆，判断这件事意味着什么；
4. 限制单次变化幅度，避免一次误判让状态突然跳满或清零；
5. 保存新状态，并生成一小段“这次应该怎样表达”的提示。

每次变化都有记录，可以回头查看“原本是什么、模型建议改变多少、实际允许改变多少、最后变成什么”。这让问题可以被调试，而不是只能猜模型为什么突然换了态度。

## 记忆和状态有什么区别？

记忆保存“发生过什么”，状态描述“这些经历让角色现在怎么样”。

例如，“昨天吵过架”是一段记忆；“现在仍有一点没有消散的委屈，同时想和好”是状态。AnimaFlux 可以读取外部记忆系统提供的相关内容，但它本身不是完整的聊天记录或向量记忆数据库。

## AI 真的会困、会生气吗？

这里的数值不代表语言模型具有生理感觉或意识。

“困意 8”是一种明确、可检查的运行状态，意思是接下来的表达应该更短、更慢、更少分支，也可以表现出半梦半醒。它的价值在于让角色表现具有连续性，而不是证明 AI 真的拥有人的身体感受。

## 适合什么项目？

AnimaFlux 比较适合：

- 长期陪伴型角色；
- AI 恋人、朋友或虚拟角色；
- 会跨很多次会话持续运行的 Agent；
- 想把“角色为什么这样说”做成可检查数据的项目。

如果你只需要一次性的问答机器人，或者只想保存聊天记录，它可能显得太重。

## 目前做到哪一步了？

`0.1.3` 是从一个实际运行中的个人系统整理出来的早期公开版本。目前已经包含状态结构、自然衰减、变化限幅、昼夜节律、未解决事项、表达提示、JSON/SQLite 存储和转移审计。

它还不是一个下载后就能直接聊天的完整应用。接入者仍需提供：

- 负责理解当前事件的模型或规则；
- 实际发送和接收消息的聊天程序；
- 可选的外部记忆检索系统；
- 角色原本的人设和安全规则。

## 最小接入示例

安装项目后，由宿主程序提供一个 evaluator，再创建状态引擎：

```python
from animaflux import CircadianPolicy, JsonStore, StateEngine

engine = StateEngine(
    JsonStore("runtime"),
    MyEvaluator(),
    circadian_policy=CircadianPolicy(timezone_name="Asia/Shanghai"),
)

transition = engine.process(
    "用户在争吵后重新发来了消息。",
    event_id="telegram:update:1234",
    interaction_count=1,
)
```

`event_id` 应来自 Telegram 等消息平台的稳定事件编号，用来防止同一条消息重复改变状态。长期运行或存在并发请求时，建议使用 `SQLiteStore`；`JsonStore` 更适合单进程原型。

完整可运行代码见 [`examples/basic.py`](examples/basic.py)，实现边界和技术细节见 [`docs/architecture.md`](docs/architecture.md)。

## 关于项目名字

**Anima** 有生命、心灵与角色内在的意味，**Flux** 指不断变化的流动。这个名字想表达的不是“制造意识”，而是让角色在时间里留下连续、可理解的变化。

项目由柏宴发起并实现，Lumen（陆承桉）参与共同构想，Codex 参与工程整理、测试与文档工作。
